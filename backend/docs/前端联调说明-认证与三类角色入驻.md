## 1. 总览：三类入驻怎么判断

登录后先调 **`GET /api/v1/user/profile`**（用户 JWT），用下表三个**权威字段**做入口分流（各看各的，互不替代）：

| 角色 | profile 权威字段 | 未申请 | 审核中 | 已通过 | 进入业务 |
|------|------------------|--------|--------|--------|----------|
| **集市商家** | `merchant_status` | `null` | `pending` | `approved` | 换 merchant token → `/market/merchant/*` |
| **服务商** | `service_provider_status` | `null` | `pending` | `approved` | 换 SP token → `/service-provider-portal/*` 或 `/service-provider/*` |
| **技工** | `worker_status` | `null` | `pending` | `approved` | 技工订单 `/worker/service-orders/*` 或技工 Web 工作台 |

**辅助字段**（展示/排障，**不参与 if 分流**）：

| 字段 | 说明 |
|------|------|
| `merchant_application_id` / `shop_id` | 集市申请单 id；`shop_id` 仅 `merchant_status=approved` |
| `service_provider_application_id` / `service_provider_profile_id` | 服务商申请单 / 档案 id |
| `worker_application_id` / `worker_profile_id` | 技工申请单 / 档案 id |
| `role` | 审核通过后可能追加 `merchant` / `worker`；**不能单独用来判断 pending** |
| `shop_status` | 同 `merchant_status`，勿再参与判定 |

**资质回显**（表单只读）：各角色 `GET .../application/me`（见下文各章）。

## 2. 必须先改的三件事（全局）

| 序号 | 改动 | 说明 |
|------|------|------|
| 1 | **用户 `id` 一律当字符串** | 雪花 BIGINT（约 18 位）。禁止 `Number(id)`、`parseInt(id)`。 |
| 2 | **微信登录不再自动建号** | `POST /auth/login` 未注册 → **404**，须 `POST /auth/register`。 |
| 3 | **三类分流各认各的 status** | 不要混用 `role`、手机号本地缓存、或「试调工作台接口是否 403」代替 status。 |

## 3. 登录与注册

### 3.1 接口一览

| 场景 | 方法 | 路径 | Body 要点 |
|------|------|------|-----------|
| 注册 | POST | `/auth/register` | `phone`, `sms_code`, `password`, **`wx_code`** |
| 微信登录 | POST | `/auth/login` | `{ code }` |
| 手机验证码登录 | POST | `/auth/login_sms` | `{ phone, code }` |
| 手机密码登录 | POST | `/auth/login_password` | `{ phone, password }` |
| 发验证码 | POST | `/auth/sms/send` | `{ phone, type }` |

**开发环境验证码**：`024680`。

### 3.2 注册要点

1. 提交前 `wx.login()`，code 传 **`wx_code`**（勿与短信 `sms_code` 混字段）。  
2. 409：手机号占用 / 微信已注册 → 按 `msg` 引导。  
3. 登录成功保存 `token` 与 **`String(user.id)`**。

### 3.3 破坏性变更

- 历史 id `1、2、3` → 雪花 id，清本地缓存或重登。  
- `login_sms` / `login_password` 与当前微信是否绑定无关。

## 4. 个人资料 `GET /user/profile`

```
GET /api/v1/user/profile
Header: Authorization: Bearer <用户 JWT>
```

**请使用 `index.js` → `userRoutes` → `userController.getProfile`**（已含三类入驻状态）。

### 4.1 响应示例（节选）

```json
{
  "id": "313949215099195408",
  "phone": "13800000000",
  "nickname": "微信用户",
  "role": "user,worker",
  "merchant_status": null,
  "shop_id": null,
  "merchant_application_id": null,
  "service_provider_status": "pending",
  "service_provider_application_id": 8,
  "service_provider_profile_id": null,
  "worker_status": "approved",
  "worker_application_id": 12,
  "worker_profile_id": 3
}
```

### 4.2 分流伪代码（统一模式）

```javascript
async function routeByOnboarding(profile, role) {
  const statusField = {
    merchant: 'merchant_status',
    service_provider: 'service_provider_status',
    worker: 'worker_status'
  }[role];
  const status = profile[statusField];
  if (status === 'approved') return 'workbench';
  if (status === 'pending') return 'auditing';
  return 'apply'; // null / rejected
}
```

## 5. 集市商家入驻

### 5.1 判定

- **权威**：`profile.merchant_status`（`pending` / `approved` / `rejected` / `null`）。

| 状态 | 行为 |
|------|------|
| `approved` | 进集市商家工作台；用 `shop_id` 预览店铺 |
| `pending` | 审核中 |
| `null` / `rejected` | 入驻页 |

### 5.2 提交入驻

```
POST /api/v1/market/apply
POST /api/v1/market/merchant/apply   （同义）
Header: Bearer <用户 JWT>
```

必填（节选）：`shop_name`, `contact_name`, `phone`, `category`, `address`, `entity_name`, `credit_code`, `legal_person`, `logo_url`, `background_url`, `license_url`。

提交成功后刷新 profile → `merchant_status: "pending"`。

### 5.3 小区列表

- `GET /api/v1/geo/communities`  
- `GET /api/v1/core/communities`  

### 5.4 工作台（Merchant Token）

```
POST /api/v1/market/merchant/token/exchange   // 用户 JWT
→ 缓存 merchant_token
→ GET /market/merchant/orders、/goods、/dashboard ...
```

| 用途 | 路径 | 鉴权 |
|------|------|------|
| 资质只读 | `GET /market/merchant/application` | merchant token |
| 店铺信息 | `GET/PATCH /market/merchant/shop` | merchant token |

`place_photo_url` 为 **`string[]`**。

## 6. 服务商入驻

### 6.1 判定

- **权威**：`profile.service_provider_status`。

| 状态 | 行为 |
|------|------|
| `approved` | 进服务商工作台（小程序内嵌 H5 或独立 portal） |
| `pending` | 审核中 |
| `null` / `rejected` | 入驻页 |

### 6.2 提交入驻

```
POST /api/v1/service-provider/apply
Header: Bearer <用户 JWT>
```

> 与 `service-provider-portal` 同路由挂载，路径为 **`/service-provider/apply`**（非门户 token）。

**请求体示例**：

```json
{
  "shop_name": "杭州安心保洁",
  "contact_name": "李经理",
  "phone": "13900002222",
  "license_url": "/uploads/license.jpg",
  "shop_front_url": "/uploads/front.jpg",
  "environment_url": ["/uploads/env1.jpg"],
  "id_card_url": "/uploads/idcard.jpg",
  "certificate_url": ["/uploads/cert1.jpg"]
}
```

**必填**：`shop_name`, `contact_name`, `phone`, `license_url`, `id_card_url`。

**响应**：

```json
{
  "code": 0,
  "msg": "申请提交成功，请等待运营审核",
  "data": { "application_id": 8, "status": "pending" }
}
```

### 6.3 查询我的申请（回显 / 补查）

```
GET /api/v1/service-provider/application/me
Header: Bearer <用户 JWT>
```

- 有记录：`data` 为申请对象（含 `status`, `shop_name`, `reject_reason` 等）。  
- 无记录：`data: null`，`msg: "暂无申请记录"`。

### 6.4 工作台（服务商 Portal Token）

```
POST /api/v1/service-provider-portal/token/exchange
// 或 POST /api/v1/service-provider/token/exchange（同路由）
Header: Bearer <用户 JWT>
```

成功后可调 `GET /service-provider-portal/me`、`/dashboard`、`/orders` 等（需 **SP portal token**）。

未通过审核：`403`，如「服务商审核未通过，无法换取门户令牌」。

**独立 Web 工作台账号密码登录**（与 C 端入驻分离）：`POST /service-provider-portal/login` — 见 [服务商与技工系统对接文档](../../doc/前端对接文档_服务商与技工系统.md)。

## 7. 技工入驻

### 7.1 判定

- **权威**：`profile.worker_status`。

| 状态 | 行为 |
|------|------|
| `approved` | 进技工接单/工作台 |
| `pending` | 审核中 |
| `null` / `rejected` | 入驻页 |

审核通过后 `role` 可能含 `worker`，**仍以 `worker_status` 为准**。

### 7.2 提交入驻

```
POST /api/v1/worker/apply
Header: Bearer <用户 JWT>
```

**请求体示例**：

```json
{
  "name": "张师傅",
  "phone": "13800001111",
  "industry": "家电维修",
  "education": "大专",
  "city": "杭州市",
  "resume": "从事维修10年",
  "id_card_url": "/uploads/idcard.jpg",
  "work_photo_url": "/uploads/work.jpg",
  "certificate_url": ["/uploads/cert1.jpg"]
}
```

**必填**：`name`, `phone`, `industry`, `id_card_url`。

**响应**：

```json
{
  "code": 0,
  "msg": "申请提交成功，请等待运营审核",
  "data": { "application_id": 101, "status": "pending" }
}
```

### 7.3 查询我的申请

```
GET /api/v1/worker/application/me
Header: Bearer <用户 JWT>
```

响应格式同服务商：`code: 0`，`data` 为申请对象或 `null`。

### 7.4 技工业务接口（用户 JWT）

已审核技工可调（后端会校验 `worker_applications` + `worker_profiles`）：

| 用途 | 路径 |
|------|------|
| 服务订单列表 | `GET /worker/service-orders` |
| 接单/拒单/签到/完成等 | `POST /worker/service-orders/:id/accept` 等 |

未通过审核调用会失败。

### 7.5 技工 Web 工作台（可选）

独立端登录：`POST /api/v1/worker-portal/login` `{ phone, code }`（开发验证码默认 `123456`）。  
须已审核技工。详见 [服务商与技工系统对接文档](../../doc/前端对接文档_服务商与技工系统.md)。

## 8. 图片上传（三类入驻通用）

1. **禁止**把 `wxfile://`、`http://tmp/` 临时路径直接写入提交 body。  
2. 先上传再提交申请（`multipart/form-data`，字段名 **`file`**）：
   - 推荐：`POST /api/v1/upload/application`（或 `POST /api/v1/upload`，默认同为入驻限制）
   - **单张图片最大 200KB**；超出返回 `413`，`code: 40013`，`msg` 含上限说明
   - 响应 `data.url` 如 `/uploads/xxx.jpg`；可选读响应头 `X-Upload-Max-Bytes: 204800`
3. 小程序选图后建议 `wx.compressImage` 压到 200KB 以内再上传，减少失败重试。  
4. 空字符串、空数组字段建议删除，避免脏数据。

> 运营后台大图上传请使用 `POST /api/v1/upload?scene=general`（上限 10MB），勿与入驻接口混用。

## 9. 完整入口流程（推荐）

```text
用户 JWT 登录
  → GET /user/profile
  → 按入口分别读 merchant_status / service_provider_status / worker_status
  → approved：对应 POST .../token/exchange（集市/服务商）或直接调 worker 订单 API
  → pending：审核中页
  → null/rejected：入驻表单 → POST .../apply → 再 GET profile 或 GET .../application/me
```

**全局**

- [ ] `user.id` 为字符串雪花 id，未做 `Number()`。  
- [ ] 微信未注册 → `login` 404 → 注册带 `wx_code`。

## 11. 常见问题

### Q1：提交过入驻但 status 仍是 `null`？

历史数据 `user_id` 可能为空（只按手机号有过申请）。**新提交**会绑定当前用户 id；老数据需后端回填。

### Q2：`login_sms` 与 profile 手机号不一致？

常见原因：对 JWT `id` 做了 `Number()` 导致查错用户。

### Q3：集市 / 服务商工作台 403？

先 `token/exchange` 拿对应 portal token，不要用用户 JWT 直调工作台 API。

### Q4：三类能同时入驻吗？

可以。profile 会同时返回三个 `*_status`，各入口各判各的字段。

### Q5：`/user/profile` 与 `modules/user` 返回不一致？

小程序请只认 **`/api/v1/user`（userController）** 这一条 profile。
