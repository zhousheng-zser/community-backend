## 2. 接口契约（与原文档一致，字段名请勿改）

### 2.1 本地集市

#### POST `/api/v1/market/payments/create`

- **鉴权**：`Authorization: Bearer <用户 token>`
- **Body**：`{ "order_no": "MK..." }`

**成功响应示例**（`code: 0`）：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "order_no": "MK202605221515186453",
    "out_trade_no": "1780625780477445148",
    "amount": "12.50",
    "pay_mode": "wechat",
    "virtual_pay": false,
    "payment_mode": "wechat",
    "wx_pay_params": {
      "timeStamp": "1710000000",
      "nonceStr": "随机串",
      "package": "prepay_id=wx...",
      "signType": "RSA",
      "paySign": "Base64签名"
    },
    "timeStamp": "1710000000",
    "nonceStr": "随机串",
    "package": "prepay_id=wx...",
    "signType": "RSA",
    "paySign": "Base64签名"
  }
}
```

**前端判定是否调起收银台**：

- ✅ 真支付：`virtual_pay !== true` 且 `signType === "RSA"` 且 `package` 以 `prepay_id=wx` 开头
- ❌ 虚拟支付：`virtual_pay === true`（当前生产已关闭，不应再出现）

#### GET `/api/v1/market/payments/status?order_no=MK...`

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "order_no": "MK...",
    "pay_status": "paid",
    "order_status": "pending_accept"
  }
}
```

前端轮询时，以下均视为已支付：`paid` / `success` / `paid_success`。

### 2.2 到家服务

- `POST /api/v1/service-orders/payments/create` — Body/响应格式与集市相同
- `GET /api/v1/service-orders/payments/status?order_no=SO...`

### 2.3 支付回调（微信 → 后端，前端无需调用）

- `POST /api/v1/market/pay/callback`
- 成功应答：`{ "code": "SUCCESS", "message": "成功" }`

## 3. 错误码（HTTP 200，`code` 非 0）

| code | 含义 | 前端建议 |
|------|------|----------|
| 20031 | 订单状态不允许支付 | 提示用户刷新订单页 |
| 20043 | 用户未绑定 openid | 引导重新微信登录 |
| 20044 | 未配置微信支付 | 联系后端（运维问题） |
| 20045 | 微信统一下单失败 | 展示 msg，可重试 create |
| 20046 | 订单金额为 0 | 联系运营确认免支付流程 |

---

## 4. 联调步骤

```
1. 小程序微信登录（确保 users.openid 有值）
2. 创建集市订单（order_status=pending_payment, pay_status=unpaid）
3. POST /market/payments/create { order_no }
4. 解析 wx_pay_params（或顶层五参），调用 wx.requestPayment
5. 轮询 GET /market/payments/status 直到 pay_status=paid
6. 跳转支付成功页
```

## 7. 常见问题

| 问题 | 原因 | 处理 |
|------|------|------|
| 仍看到 `signType: MD5` | 旧缓存或未部署 | 强刷 / 确认后端已重启 |
| `virtual_pay: true` | 虚拟支付未关或缺配置 | 后端设 `MARKET_PAY_VIRTUAL_SUCCESS=false` |
| 20043 无 openid | 非微信登录或 openid 未入库 | 重新 wx.login + 后端登录 |
| prepay_id 过期 | 超过约 2 小时 | 重新调用 payments/create |
| 支付成功但 status 仍 unpaid | 回调未达或验签失败 | 查后端日志 `pay/callback` |
| status 请求/响应 order_no 不一致 | 后端误返回用户最近流水 | 严格按 query.order_no 查库 |

## 8. 后端排查语料（扣款成功但订单仍待付款）

**环境：** `https://jshsp1.eds-tech.cn/api/v1`

**典型现象：**

- 用户微信账单已扣款（如 ¥0.01）
- `GET /market/payments/status?order_no=MK...` 持续返回 `pay_status=unpaid`、`tx_pay_status=created`
- 偶发：请求 URL 带 `order_no=A`，响应体却是 `order_no=B`

**请后端排查：**

1. `POST /api/v1/market/pay/callback` 是否收到对应 `out_trade_no` 的通知
2. 回调验签 / rawBody 中间件是否导致 decrypt 失败（见 `backend/src/index.js`）
3. **公钥模式**：须配置有效 `WX_PAY_PUBLIC_KEY` + `WX_PAY_PUBLIC_KEY_ID`（占位内容会导致验签 401，启动日志会有告警）
4. SQL：
   ```sql
   SELECT * FROM market_pay_transactions WHERE order_no = 'MK...' OR out_trade_no = '...';
   SELECT order_no, order_status, pay_status, paid_at FROM market_orders WHERE order_no = 'MK...';
   ```
5. 微信商户平台按 `out_trade_no` 查交易状态与 `transaction_id`
6. 若微信已成功、本地未更新：
   - **自动**：轮询 `GET /payments/status` 时后端会主动 V3 查单补偿（`unpaid` + `tx created`）
   - **手动**：`node backend/scripts/reconcile-wechat-pay.js --order-no MK...`

**期望修复：**

- `payments/status` 严格按 `order_no` 返回（响应 `order_no` 必须与请求一致；路由绑定 `marketPaymentController`）
- 回调或查单补偿落库：`pay_status=paid`、`order_status=pending_accept`
