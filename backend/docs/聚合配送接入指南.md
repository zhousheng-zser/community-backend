# 聚合配送接入指南

本文说明本地集市多店铺接入**美团配送开放平台**（首选）及后续扩展蜂鸟/达达/顺丰/闪送的步骤。

## 架构说明

| 层级 | 配置位置 | 说明 |
|------|----------|------|
| 平台凭证 | `.env` 中 `MEITUAN_APP_KEY` / `MEITUAN_SECRET` | 全平台一套，所有店铺共用 |
| 门店 ID | 表 `merchant_shop_delivery_bindings` | 每店一条，`provider=meituan`，`external_shop_id` 即美团 `shop_id` |
| 发单 | `POST .../delivery/launch` | 后端按订单 `shop_id` 查绑定表，调用 `order/createByShop` |

多个店铺可共用一个微信小程序；配送与支付、AppID 独立配置。

## 美团配送开放平台入驻

1. 打开 [美团配送技术服务合作中心](https://peisong.meituan.com/open/guide)，以**企业主体**注册并提交资质。
2. 审核约 3–5 个工作日，通过后进入「开发者管理」。
3. 申请 **测试** AppKey/Secret（另有正式密钥，上线前切换）。
4. 在开发者后台配置回调 URL：
   ```
   https://jshsp1.eds-tech.cn/api/v1/market/delivery/webhook/meituan
   ```
5. 联调完成后联系美团运营做功能验收，再使用正式 AppKey。

### 测试门店

- 文档规定测试发单 `shop_id` 固定为 **`test_0001`**。
- `shop/create` 可用于练习创建门店，但测试推单仍建议使用 `test_0001`。

### `.env` 示例

```bash
DELIVERY_MOCK=0
PUBLIC_API_BASE=https://jshsp1.eds-tech.cn/api/v1

MEITUAN_APP_KEY=你的测试AppKey
MEITUAN_SECRET=你的测试Secret
MEITUAN_SERVICE_CODE=4012
```

> 多店模式**不要**依赖全局 `MEITUAN_SHOP_ID`，改用绑定表按店维护。

## 店铺绑定方式

### 1. CLI 脚本（推荐首店联调）

```bash
cd backend

# 无凭证：Mock 绑定，验证发单/进度全链路
node scripts/bind-test-shop-delivery.js --shop-no TEST001 --provider meituan --mock

# 有测试凭证：绑定美团测试门店
node scripts/bind-test-shop-delivery.js --shop-no TEST001 --provider meituan --external-shop-id test_0001

# 有测试凭证：调用 shop/create 注册
node scripts/bind-test-shop-delivery.js --shop-no TEST001 --provider meituan --register
```

脚本会自动补全缺失的经纬度/电话/地址（合川路地铁站附近示例坐标）。

### 2. 商家 API

需商家登录 Token（`Authorization: Bearer ...`）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/market/merchant/delivery/bindings` | 查询当前店铺各平台绑定状态 |
| POST | `/api/v1/market/merchant/delivery/bindings/meituan/register` | 用店铺资料调美团 `shop/create` |
| POST | `/api/v1/market/merchant/delivery/bindings/meituan/test` | 绑定测试门店，body 可选 `{ "external_shop_id": "test_0001" }` |

### 3. 发单与查进度

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/market/merchant/orders/:orderNo/delivery/options` | 可选配送方式（按店过滤） |
| POST | `/api/v1/market/merchant/orders/:orderNo/delivery/launch` | body: `{ "provider": "meituan" }` |
| GET | `/api/v1/market/merchant/orders/:orderNo/delivery/track` | 配送进度 |

买家端：`GET /api/v1/market/orders/:orderNo/delivery/track`

## 联调检查清单

1. 店铺资料：`latitude`、`longitude`、`contact_phone`、`address` 已填写（GCJ-02 坐标）。
2. 订单：`receiver_latitude`、`receiver_longitude` 已写入（下单时选地图地址）。
3. 绑定表存在该店 `provider=meituan` 且 `status=active`。
4. `DELIVERY_MOCK=1` 时可无 AppKey，走 Mock 配送进度。
5. `DELIVERY_MOCK=0` 时需 AppKey + 绑定 `test_0001` 或正式 shop_id。

## 饿了么蜂鸟即配（第二期）

- 入口：[蜂鸟即配开放平台](https://open-anubis.ele.me/)
- 环境变量：`ELEME_APP_KEY`、`ELEME_SECRET`
- 每店 `external_shop_id` / `external_shop_code` 写入绑定表 `provider=eleme`
- Webhook：`/api/v1/market/delivery/webhook/eleme`

## 后续扩展（达达 / 顺丰 / 闪送）

绑定表 `provider` 已预留：`dada`、`sf`、`shansong`。接入步骤：

1. 新增 `backend/src/services/delivery/xxxDelivery.client.js`
2. 在 `marketDelivery.service.js` 增加 provider 分支
3. 在 `shopDeliveryBinding.service.js` 增加注册/绑定方法
4. 管理端批量：`shop/create` 循环 + upsert binding
